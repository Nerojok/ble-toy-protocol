# 帧表

**通用结构**：20 字节定长，经特征 `fe02`（handle `0x000c`）写出，必须用 Write Request（bleak 里 `response=True`）。

```
偏移   0     1     2     3     4     5 .. 19
含义   通道  0x12  参数  0x00  附加  补 0x00
```

第 1 字节固定 `0x12`，是目前唯一观察到的常量；它可能是个"命令类"标记，但没验证过别的取值，所以不猜。

---

## 通道 0x01 — 震动模式

```
01 12 NN 00 64  00 ...
              ↑ 0x64 = 100，含义未确认（可能是百分比或速度权重）
NN = 0x00 .. 0x04   实测有五种明显不同的节奏
```

重放记录：`01 12 00` → `01 12 01` → … 逐个切换，节奏变化可辨。

---

## 通道 0x02 — 吸吮模式

```
02 12 NN 00 64  00 ...
NN = 0x00 .. 0x05   标称六档
```

**注意（证据等级：弱）**：测试时设备仍在真空包装中，机械动作受限，前三档听感几乎一致，第 4 档尾部有吸气声，第 5 档更短。**拆封后需要重测。** 这份表把范围记下来，但不要当作已确认的档位行为。

---

## 通道 0x03 — 震动强度

```
03 12 XX 00 00  00 ...
XX = 0x00 .. 0xFF   线性，越大越强
```

实测：`03 12 20` → `03 12 80` → `03 12 FF` 强度明显递增；`03 12 00` 立刻停。

**保活帧**：App 空闲时约每秒发一次 `03 12 00 00 64`。不清楚是心跳还是"每秒重申一次强度为零"，但它是唯一周期性的写入。

---

## 读方向（这台设备基本没有）

```
fe01   从不返回数据
ff14   从不返回数据
fe02   notify 上只有 64 00 00，约 10 秒一次（心跳）
```

**结论：没有可读的传感数据。** 宣传里的"压感"是设备内部闭环（压感直接改强度），不对外播。

---

## 无效路径（别再试）

```
ff15   服务 0xff12 下的写特征：15 种裸命令 + 7 字节帧，全部零反应
02 xx / 05 xx  猜的通道前缀：无反应
```

---

## 如果你手上是同款想复现

1. 先 `python tools/ble_probe.py gatt <ADDR>`，确认你设备的写特征和这里一致
2. **不要**直接照抄 `fe02`，先抓一次你自己 App 的操作包——同款不同固件可能换特征
3. 从 `03 12 00`（停止）开始试，再往上加，别一上来就 FF
